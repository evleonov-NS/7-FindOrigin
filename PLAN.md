# План реализации FindOrigin

Поэтапный порядок действий на основании `PROJECT.md`.

---

## Этап 0. Подготовка окружения

1. Инициализировать Next.js-проект в репозитории.
2. Подключить TypeScript, ESLint и базовую структуру папок (`app/`, `lib/`, `types/`).
3. Добавить переменные окружения:
   - `TELEGRAM_BOT_TOKEN`
   - ключ AI-провайдера
   - при необходимости — ключ поискового API
4. Настроить деплой на Vercel (проект, env, домен webhook).
5. Создать бота через BotFather и сохранить токен.

**Критерий готовности:** проект локально запускается, на Vercel деплоится пустой Next.js-приложение.

---

## Этап 1. Минимальный Telegram webhook

Цель: бот принимает сообщение и отвечает «эхом».

1. Создать Route Handler `POST /api/telegram` (или `/api/webhook`).
2. Разобрать входящий `update` от Telegram.
3. Извлечь `chat.id` и `text` из `update.message`.
4. Отправить ответ через Telegram API (`sendMessage`).
5. Всегда быстро возвращать `200 OK` (без долгих операций в этом запросе).
6. Зарегистрировать webhook на URL Vercel.
7. Проверить: сообщение в Telegram → ответ бота.

**Критерий готовности:** бот отвечает на любой текст в чате.

---

## Этап 2. Базовый UX бота

1. Обработать команды `/start` и `/help` с краткой инструкцией.
2. Отличать пустые/неподдерживаемые сообщения (стикеры, фото без подписи и т.п.).
3. Отправлять пользователю статус «Ищу источник…» до начала тяжёлой работы.
4. Оформить единый шаблон ответа с источниками и уверенностью (заготовка под этап 5).

**Критерий готовности:** пользователь понимает, что отправлять, и получает понятные ответы об ошибках ввода.

---

## Этап 3. Нормализация ввода

Цель: получить текст для анализа из текста или ссылки.

1. Определить тип ввода: обычный текст или ссылка на Telegram-пост.
2. Для текста — использовать его как есть (с очисткой пробелов/служебных символов).
3. Для ссылки на пост — извлечь текст поста (через доступный API/парсинг публичного поста; зафиксировать ограничения, если пост приватный).
4. Вернуть единую структуру: `{ sourceType, rawInput, text }`.
5. При невозможности извлечь текст — сообщить пользователю об ошибке.

**Критерий готовности:** и текст, и публичная ссылка на пост превращаются в строку для анализа.

---

## Этап 4. Извлечение фактов из текста

Цель: выделить сущности для поиска.

1. Реализовать модуль извлечения:
   - ключевые утверждения
   - даты
   - числа
   - имена
   - ссылки
2. На первом проходе можно использовать AI (структурированный JSON-ответ) либо комбинацию правил + AI.
3. Сохранять результат в типизированной структуре (например, `ExtractedFacts`).
4. Покрыть юнит-тестами несколько типичных примеров текстов.

**Критерий готовности:** по входному тексту стабильно получается набор фактов для поиска.

---

## Этап 5. Поиск кандидатов-источников

Цель: найти 1–3 возможных первоисточника.

1. Сформировать поисковые запросы из извлечённых фактов.
2. Выполнить поиск по внешнему API (официальные сайты, новости, блоги, исследования).
3. Отфильтровать мусор и дубликаты, оставить топ-кандидатов.
4. Для каждого кандидата сохранить: URL, заголовок, сниппет/краткое содержание.

**Критерий готовности:** по фактам возвращается короткий список релевантных ссылок-кандидатов.

---

## Этап 6. AI-сравнение смысла и оценка уверенности

Цель: сравнить смысл исходного текста с кандидатами, а не буквальное совпадение.

1. Для каждого кандидата оценить семантическое совпадение с исходным текстом/утверждениями.
2. Присвоить оценку уверенности (например, 0–100% или уровни: высокая / средняя / низкая).
3. Оставить 1–3 лучших источника.
4. Сформировать понятное объяснение: почему источник считается релевантным.
5. Собрать финальный ответ для Telegram (ссылки + уверенность + краткий комментарий).

**Критерий готовности:** бот выдаёт 1–3 ссылки с оценкой уверенности по смыслу.

---

## Этап 7. Асинхронная обработка (чтобы webhook оставался быстрым)

Важно по спецификации: webhook должен быстро вернуть `200 OK`.

1. В webhook только: принять update, валидировать, поставить задачу, ответить 200.
2. Тяжёлую цепочку (извлечение → поиск → AI) вынести из синхронного запроса:
   - вариант A: ответить «принято» и продолжить обработку через фоновый механизм, совместимый с Vercel;
   - вариант B: сразу отправить «Ищу…», а результат — вторым сообщением после обработки (с контролем лимитов serverless).
3. Обработать таймауты и ошибки AI/поиска без «зависания» для пользователя.
4. Логировать ошибки (Vercel logs / простой logger).

**Критерий готовности:** webhook отвечает быстро; пользователь всё равно получает итоговый результат.

---

## Этап 8. Стабилизация и деплой

1. Добавить защиту webhook (секретный путь или проверка `secret_token` Telegram).
2. Ограничить частоту запросов (простой rate limit на `chat.id`).
3. Прогнать ручные сценарии:
   - текст с фактами
   - ссылка на публичный Telegram-пост
   - бессмысленный/короткий ввод
   - недоступная ссылка
4. Проверить работу на Vercel в production.
5. Зафиксировать в README: как задать env, как поставить webhook, как пользоваться ботом.

**Критерий готовности:** production-бот стабильно находит источники по тексту и ссылке.

## Рекомендуемый порядок внутри каждого этапа

1. Сделать минимально рабочий вертикальный срез.
2. Проверить вручную в Telegram.
3. Только потом усложнять (AI, поиск, асинхронность).
4. Не начинать этапы 4–6, пока этапы 1–3 не работают end-to-end.
